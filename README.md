# cbeta-ebook-renamer

把 CBETA 電子書的檔名從**經號**批次改成**經號＋中文經名**。

```
T0001.epub   →   T0001_長阿含經.epub
T0374.pdf    →   T0374_大般涅槃經.pdf
T0001/       →   T0001_長阿含經/      （docx、odt 是一部典籍一個資料夾）
```

CBETA 官方發佈的電子書一律以經號命名（`T0001.epub`），好處是跨平台、跨語系都不會出問題；
但對讀者來說很難從檔名認出是哪一部經。本工具讓有需要的使用者**在自己電腦上**做這個轉換，
官方的下載檔維持原狀不受影響。

## 支援的格式

| 格式 | 結構 | 改名對象 | 支援狀況 |
| --- | --- | --- | --- |
| **EPUB** | `T/T0001.epub` | 檔案 | ✅ |
| **PDF**（分三次下載） | `T/T0001.pdf` | 檔案 | ✅ 三份分開執行即可 |
| **docx** | `T/T0001/T0001_001.docx` | **資料夾** | ✅ 目前需自備對照表（見下） |
| **odt** | `T/T0001/T0001_001.odt` | **資料夾** | ✅ 目前需自備對照表（見下） |

docx 與 odt 是**一部典籍一個資料夾**，裡面再按卷分成 `T0001_001.docx`、`T0001_002.docx`……
所以改名的對象是**經號資料夾**，卷檔一律維持原名：

```
T/T0001/               →   T/T0001_長阿含經/
  ├── T0001_001.docx         ├── T0001_001.docx   ← 不動
  └── T0001_002.docx         └── T0001_002.docx   ← 不動
```

卷檔的名字（`T0001_001`）形狀剛好和「經號_經名」一樣，程式會先把它認出來，
不會誤把卷號當成經名。不在任何經號資料夾底下的孤立卷檔則會明確略過。

### docx / odt 目前需要自備對照表

現在線上的 `cbeta-docx.zip` 與 `cbeta-odt.zip` 解開後是 `docx/`、`odt/` 資料夾，
而且**不含 `filelist_*.txt` 對照表**（epub 與 pdf 的壓縮檔都有），
程式沒有對照表就無從得知經名。在新版發佈之前，請先自行補一份：

1. 下載 epub 或 pdf 版的壓縮檔（這兩種的對照表內容完全相同，任何一份都可以）。
2. 把裡面的 `filelist_2026r2.txt` 複製到 docx／odt 解壓後的最上層，也就是和 `T/`、`X/` 同一層。

```
docx/
├── filelist_2026r2.txt        ← 暫時從 epub 或 pdf 版複製過來
├── cbeta-ebook-renamer.command
├── T/
│   └── T0001/
│       ├── T0001_001.docx
│       └── ...
└── X/
```

epub 的對照表是完整的 4899 筆，比 docx／odt 實際收錄的部數多，這不影響使用，程式也不會發出警告。

> **新版發佈後就不用這一步了。** CBETA 已確定在 docx／odt 的壓縮檔中內附對照表，
> 並且把最上層資料夾改成帶版本字串的 `cbeta_docx_2026r2/`、`cbeta_odt_2026r2/`（與 epub／pdf 一致）。
> 本工具兩種結構都支援，不必更新程式。線上檔案的更新時程另行公布。
> （單部下載的 `T0099.zip` 一律不含對照表，與 epub／pdf 相同。）

docx 與 odt 目前（2026r2）只收錄大正藏（T，2457 部）與卍續藏（X，1230 部），共 3687 部。

### 為什麼不要混用兩種對照表？

docx／odt 內附的對照表是 CBETA 從書目資料庫（authority catalog）直接產生的，
**不是 epub 那一份的複本**，只收錄該壓縮檔實際包含的 3687 筆。
兩者絕大多數相同，但有少數幾筆的**經名**寫法不一樣，例如：

| 經號 | epub 版 | docx／odt 版 |
| --- | --- | --- |
| T1567 | `大乘中觀釋論(第1卷-第9卷)` | `大乘中觀釋論`（括號是 epub 分卷才加的） |
| T2862 等 | 組字式 `[厄*殳]` | Unicode 罕見字（如 𭮨 U+2DBA8） |

所以同一批 docx 先用甲版對照表改名、之後又用乙版跑一次，這幾筆會被判定成「需要更新」而再改一次名。
程式不會默默動手——預覽中會標示 `[既有名稱與對照表不符，將更新]`，看到時確認一下是不是拿錯對照表即可。

建議**固定使用該壓縮檔自己內附的那一份**。

## 下載與使用

1. 到 [Releases](../../releases) 下載對應作業系統的壓縮檔：

   | 作業系統 | 下載 | 解壓後的執行檔 |
   | --- | --- | --- |
   | macOS（Apple Silicon，M 系列） | `…-darwin-arm64.zip` | `cbeta-ebook-renamer.command` |
   | macOS（Intel） | `…-darwin-amd64.zip` | `cbeta-ebook-renamer.command` |
   | Windows（一般 x64） | `…-windows-amd64.zip` | `cbeta-ebook-renamer.exe` |
   | Windows（Arm64） | `…-windows-arm64.zip` | `cbeta-ebook-renamer.exe` |
   | Linux | `…-linux-amd64.tar.gz` | `cbeta-ebook-renamer` |

2. 解壓縮，把執行檔放進解壓後的 `cbeta_epub_2026r2`（或 `cbeta_pdf_1_2026r2`、`docx`、`odt`）
   資料夾裡，也就是有 `filelist_2026r2.txt` 的那一層。
3. 直接雙擊執行。程式會先列出預覽，確認後才會動手。

```
cbeta_epub_2026r2/
├── filelist_2026r2.txt           ← 經號與經名的對照表
├── cbeta-ebook-renamer.command   ← 把執行檔放這裡（Windows 是 .exe）
├── T/
│   ├── T0001.epub
│   └── ...
└── X/
```

> **為什麼 macOS 版叫 `.command`？**
> Finder 是依副檔名決定由哪個程式開啟檔案的。`.command` 會交給「終端機」執行，
> 這個工具需要終端機視窗來顯示預覽並讓你確認。
> 若把它改成沒有副檔名、但檔名中帶有點號的名字（例如 `cbeta-ebook-renamer-1.0.0`），
> macOS 會誤判成未知類型的文件，雙擊時只會跳出「未設定任何應用程式來打開文件」。
>
> **為什麼是壓縮檔而不是裸執行檔？**
> 從瀏覽器直接下載的裸檔不帶執行權限（`+x`），無法雙擊；zip 與 tar 會保留權限位元。

### 第一次開啟時的安全性提示

執行檔沒有經過程式碼簽章，作業系統會先攔下來，這是正常現象：

- **macOS**（Sequoia 15 以後）：雙擊會跳出
  「未打開『cbeta-ebook-renamer.command』／Apple 無法驗證…是否為惡意軟體」。

  1. 按「**完成**」。**不要按「丟到垃圾桶」**——那是預設反白的按鈕，按下去檔案就沒了。
  2. 到 **系統設定 → 隱私權與安全性**，捲到「安全性」區塊，會看到剛才被擋下的項目，
     按「**強制打開**」。
  3. 回到 Finder 再雙擊一次即可。

  每台電腦只需做一次。（舊版 macOS 是按住 Control 點一下執行檔 → 選「打開」；
  此方式在 Sequoia 之後已失效。）
  熟悉終端機的話也可以直接執行 `xattr -d com.apple.quarantine cbeta-ebook-renamer.command`，
  效果相同。
- **Windows**：出現「Windows 已保護您的電腦」時，點「**其他資訊**」→「**仍要執行**」。

## 命令列用法

```bash
cbeta-ebook-renamer                                  # 放在 epub 資料夾裡直接執行
cbeta-ebook-renamer -dry-run ~/Downloads/cbeta_epub_2026r2   # 只預覽，不改任何東西
cbeta-ebook-renamer -yes     ~/Downloads/cbeta_epub_2026r2   # 不詢問直接執行（供腳本使用）
cbeta-ebook-renamer -restore ~/Downloads/cbeta_epub_2026r2   # 改回原本的經號檔名
cbeta-ebook-renamer -dry-run ~/Downloads/docx                # docx/odt 改的是經號資料夾
```

（macOS 的執行檔名為 `cbeta-ebook-renamer.command`，Windows 為 `cbeta-ebook-renamer.exe`，
在命令列請用實際的檔名。）

| 選項 | 說明 |
| --- | --- |
| `-dry-run` | 只顯示預覽，不實際改名 |
| `-yes` | 略過確認直接執行 |
| `-restore` | 還原：把「經號_經名」改回「經號」 |
| `-log <路徑>` | 改名紀錄檔位置，預設 `rename_log.csv`，設為空字串則不產生 |
| `-list <數量>` | 預覽時最多列出幾筆，預設 20，設 `0` 列出全部 |
| `-ext <副檔名>` | 要處理的副檔名，預設 `.epub,.pdf,.docx,.odt` |
| `-version` | 顯示版本 |

## 設計說明

### 為什麼保留經號前綴？

實測 2026r2 版的 4899 部典籍中，**有 241 個檔案的經名會與同資料夾內其他典籍重複**
（大正藏 71 組、卍續藏 20 組、藏外 10 組……例如「大般涅槃經」有 3 部、「雜阿含經」有 2 部）。
若直接用純經名當檔名，這些檔案會互相覆蓋而且不會有任何警告。保留經號前綴可以：

- 徹底避免檔名衝突
- 維持原本依經號排列的順序（純經名排序會依編碼跳動）
- 可逆，隨時用 `-restore` 改回去
- 與 EPUB 內部的 `dc:title`（`T0001 長阿含經`）格式一致

### docx / odt 為什麼只改資料夾？

也可以把卷檔一起改成 `T0001_長阿含經_001.docx`，但這樣做：

- 檔名會長很多，最長的經名加上卷號會讓 Windows 的 260 字元路徑上限變得相當緊繃；
- 資料夾名已經帶著經名了，卷檔再重複一次沒有增加資訊；
- 卷檔不動，`-restore` 只需要把資料夾改回去，出錯的機會最小。

### 檔名安全性處理

| 狀況 | 2026r2 實際數量 | 處理方式 |
| --- | --- | --- |
| 組字式經名 `[峚-大+(企-止)]𡇪大道心驅策法` | 1 | 原樣保留，`[ ] ( ) + -` 在 macOS 與 Windows 都是合法檔名字元 |
| Unicode 擴充區漢字（𤫞 𦼮 𤙖 𪘨 𡇪 𤘽） | 7 | 原樣保留。檔名合法，只是系統缺字型時會顯示成方框 |
| 全形空格 U+3000 | 24 | 原樣保留 |
| `\ / : * ? " < > \|` 等非法字元 | 0 | 保險起見仍會換成底線 |
| 經名結尾的半形空白或句點 | 0 | 會去除（Windows 不允許） |
| 經名長度（最長 57 字 ≈ 171 bytes） | — | 未超過 255 bytes 上限；程式仍設有 200 bytes 的截斷保險 |

另外程式**不做 Unicode 正規化**（NFC/NFD），完全依照 `filelist` 提供的字串寫入，
避免在不同檔案系統之間產生看起來一樣、實際位元組不同的檔名。

### 安全機制

- 預設先顯示預覽並要求確認，才會實際動手。
- **絕不覆蓋既有檔案**：目標檔名若已被佔用，該筆會標記為「衝突」並跳過。
- 檔名比對採不分大小寫（APFS 與 NTFS 預設不分大小寫），避免漏判衝突。
- **可重複執行**：已經改過名的檔案會自動略過。
- 使用 rename 而非複製，不會佔用額外的磁碟空間（解壓後約 1 GB）。
- 每次執行都會產生 `rename_log.csv` 對照紀錄（含 BOM，Windows 的 Excel 可直接開啟）。
- 自動比對資料夾與對照表的版本字串、檔案數量，不一致時提出警告。

### 已知限制

- 若解壓到路徑很深的位置，加上最長的經名可能逼近 Windows 的 260 字元路徑上限。
  程式會對超過 240 字元的路徑提出警告（docx／odt 因為多了一層資料夾，計算時會把卷檔的長度算進去）。
  建議解壓到較短的路徑，例如 `D:\cbeta\`。
- 對照表以逗號分隔，若未來 CBETA 的經名中出現半形逗號，解析會出錯（目前 4899 筆皆無）。
- Windows 版本目前只做過交叉編譯與靜態檢查，尚未在實機上實際跑過。
- 目前線上的 docx 與 odt 下載檔不含對照表，需自行從 epub 或 pdf 版複製一份；
  且最上層資料夾叫 `docx`／`odt`，不帶版本字串，因此無法自動比對資料夾與對照表的版本是否一致。
  新版發佈後這兩點都會解決，原因見上方「支援的格式」。
- PDF 版分三次下載，每一份都附完整的 4899 筆對照表，所以單獨處理某一份時
  「檔案數少於對照表筆數」是正常的，程式不會為此發出警告。
  三份的對照表內容完全相同（md5 一致），隨便用哪一份都可以。

## 從原始碼建置

需要 [Go](https://go.dev/dl/) 1.21 以上。

```bash
go test ./...    # 執行測試
make build       # 建置目前平台
make dist        # 建置全部平台到 dist/
```

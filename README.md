# cb-ren-bat

把 CBETA 電子書（EPUB）的檔名從**經號**批次改成**經號＋中文經名**。

```
T0001.epub   →   T0001_長阿含經.epub
T0374.epub   →   T0374_大般涅槃經.epub
```

CBETA 官方發佈的 EPUB 一律以經號命名（`T0001.epub`），好處是跨平台、跨語系都不會出問題；
但對讀者來說很難從檔名認出是哪一部經。本工具讓有需要的使用者**在自己電腦上**做這個轉換，
官方的下載檔維持原狀不受影響。

## 下載與使用

1. 到 [Releases](../../releases) 下載對應作業系統的執行檔。
2. 把執行檔放進解壓後的 `cbeta_epub_2026r2` 資料夾裡（就是有 `filelist_2026r2.txt` 的那一層）。
3. 直接雙擊執行。程式會先列出預覽，確認後才會動手。

```
cbeta_epub_2026r2/
├── filelist_2026r2.txt   ← 經號與經名的對照表
├── cb-ren-bat            ← 把執行檔放這裡
├── T/
│   ├── T0001.epub
│   └── ...
└── X/
```

### 第一次開啟時的安全性提示

執行檔沒有經過程式碼簽章，作業系統會先攔下來，這是正常現象：

- **macOS**（Sequoia 15 以後）：雙擊會出現「無法打開，因為無法驗證開發者」，按「完成」，
  接著到 **系統設定 → 隱私權與安全性**，捲到「安全性」區塊，會看到剛才被擋下的項目，
  按「**強制打開**」，然後再雙擊一次即可。
  （舊版 macOS 是按住 Control 點一下執行檔 → 選「打開」；此方式在 Sequoia 之後已失效。）
  熟悉終端機的話也可以直接執行 `xattr -d com.apple.quarantine cb-ren-bat`。
- **Windows**：出現「Windows 已保護您的電腦」時，點「**其他資訊**」→「**仍要執行**」。

## 命令列用法

```bash
cb-ren-bat                                  # 放在 epub 資料夾裡直接執行
cb-ren-bat -dry-run ~/Downloads/cbeta_epub_2026r2   # 只預覽，不改任何東西
cb-ren-bat -yes     ~/Downloads/cbeta_epub_2026r2   # 不詢問直接執行（供腳本使用）
cb-ren-bat -restore ~/Downloads/cbeta_epub_2026r2   # 改回原本的經號檔名
```

| 選項 | 說明 |
| --- | --- |
| `-dry-run` | 只顯示預覽，不實際改名 |
| `-yes` | 略過確認直接執行 |
| `-restore` | 還原：把「經號_經名」改回「經號」 |
| `-log <路徑>` | 改名紀錄檔位置，預設 `rename_log.csv`，設為空字串則不產生 |
| `-list <數量>` | 預覽時最多列出幾筆，預設 20，設 `0` 列出全部 |
| `-version` | 顯示版本 |

## 設計說明

### 為什麼保留經號前綴？

實測 2026r2 版的 4899 部典籍中，**有 241 個檔案的經名會與同資料夾內其他典籍重複**
（大正藏 71 組、卍續藏 20 組、藏外 10 組……例如「大般涅槃經」有 3 部、「雜阿含經」有 2 部）。
若直接用純經名當檔名，這些檔案會互相覆蓋而且不會有任何警告。保留經號前綴可以：

- 徹底避免檔名衝突
- 維持原本依經號排列的順序（純經名排序會依編碼跳動）
- 可逆，隨時用 `-restore` 改回去
- 與 EPUB 內部的 `dc:title`（`T0001 長阿含經`）格式一致

### 檔名安全性處理

| 狀況 | 2026r2 實際數量 | 處理方式 |
| --- | --- | --- |
| 組字式經名 `[峚-大+(企-止)]𡇪大道心驅策法` | 1 | 原樣保留，`[ ] ( ) + -` 在 macOS 與 Windows 都是合法檔名字元 |
| Unicode 擴充區漢字（𤫞 𦼮 𤙖 𪘨 𡇪 𤘽） | 7 | 原樣保留。檔名合法，只是系統缺字型時會顯示成方框 |
| 全形空格 U+3000 | 24 | 原樣保留 |
| `\ / : * ? " < > \|` 等非法字元 | 0 | 保險起見仍會換成底線 |
| 經名結尾的半形空白或句點 | 0 | 會去除（Windows 不允許） |
| 經名長度（最長 57 字 ≈ 171 bytes） | — | 未超過 255 bytes 上限；程式仍設有 200 bytes 的截斷保險 |

另外程式**不做 Unicode 正規化**（NFC/NFD），完全依照 `filelist` 提供的字串寫入，
避免在不同檔案系統之間產生看起來一樣、實際位元組不同的檔名。

### 安全機制

- 預設先顯示預覽並要求確認，才會實際動手。
- **絕不覆蓋既有檔案**：目標檔名若已被佔用，該筆會標記為「衝突」並跳過。
- 檔名比對採不分大小寫（APFS 與 NTFS 預設不分大小寫），避免漏判衝突。
- **可重複執行**：已經改過名的檔案會自動略過。
- 使用 rename 而非複製，不會佔用額外的磁碟空間（解壓後約 1 GB）。
- 每次執行都會產生 `rename_log.csv` 對照紀錄（含 BOM，Windows 的 Excel 可直接開啟）。
- 自動比對資料夾與對照表的版本字串、檔案數量，不一致時提出警告。

### 已知限制

- 若把 EPUB 解壓到路徑很深的位置，加上最長的經名可能逼近 Windows 的 260 字元路徑上限。
  程式會對超過 240 字元的路徑提出警告。建議解壓到較短的路徑，例如 `D:\cbeta\`。
- 對照表以逗號分隔，若未來 CBETA 的經名中出現半形逗號，解析會出錯（目前 4899 筆皆無）。
- Windows 版本目前只做過交叉編譯與靜態檢查，尚未在實機上實際跑過。

## 從原始碼建置

需要 [Go](https://go.dev/dl/) 1.21 以上。

```bash
go test ./...    # 執行測試
go build         # 建置目前平台
make dist        # 建置全部平台到 dist/
```
